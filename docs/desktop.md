# 桌面浮窗：把卡片搬到 DSH 窗口外

> macOS 专属能力（AppKit + WebKit）。Windows / Linux 的等价壳以后有需要再做。

Agent Tree 卡片平时长在 DSH 窗口里，网页画不出浏览器视口之外——切到别的应用它就看不见了。
**桌面浮窗**把同一张卡片交给一个独立的小进程来画：透明、无边框、置顶、跟随所有 Space，
任何应用在前台都能看到它，点一行照样跳回 DSH 打开那条会话。

浮窗里的卡片和页内卡片**是同一套 React 组件与皮肤**（复用 `client.js` 的 `MiniInner`），
所以外观、交互、胶囊收起、更新面板完全一致；区别只是数据不再来自 DSH 的内存，而是绕了一跳：

```
DSH 页面（浏览器）                          桌面壳（desktop/ 产物）
┌────────────────────────────┐             ┌────────────────────────────────┐
│ client.js 发布器：每 1s POST │ ──────────▶ │ GET /local/dsh-agent-tree/dock/ │
│ 裁剪后的渲染快照             │             │ state（带握手 token）轮询        │
│                            │             │        │ 注入 dock.html          │
│ openSession ◀──────────────┼─────────────┤ MiniInner 渲染（页面零网络）      │
│        ▲ 宿主排队 action    │ ◀────────── │ 点行 → POST /dock/action        │
└────────────────────────────┘             └────────────────────────────────┘
```

## 安装与启动

插件本身 npm 安装即可；桌面壳是本地编译的小二进制（无第三方依赖，swiftc 一条命令）：

```bash
# 装好插件后，浮窗还要单独启动（它是个独立进程，装插件不会自动拉起）
npx -p dsh-plugin-agent-tree dsh-agent-tree-dock        # 首次运行会自动编译

# 或者在插件包目录里（~/.dsh/profiles/<profile>/node_modules/dsh-plugin-agent-tree）
npm run dock          # = docker:build + 启动
```

前提：

1. 本机有一个装了 dsh-plugin-agent-tree 的 dsh 实例在跑；
2. 那个实例的 web 页面在浏览器里打开着——快照是**浏览器端**发布的，页面没开时浮窗显示
   「等待 DSH 页面连接…」，页面一开 1 秒内就有数据。

壳启动时自动读 `$DSH_HOME`（默认 `~/.dsh`）里的 `agent-tree-dock-<端口>.json`（握手文件，
宿主插件在 webServer 就绪后写入，权限 0600，内容只有 origin / port / token）。
同机多个 dsh 实例时取最新的一个，也可以手动指定：

```bash
./desktop/build/dsh-agent-tree-dock --origin=http://127.0.0.1:51638
./desktop/build/dsh-agent-tree-dock --port=51638 --token=<握手文件里的 token>
./desktop/build/dsh-agent-tree-dock --verbose    # 轮询 / 布局 / 动作日志 → stderr
./desktop/build/dsh-agent-tree-dock --reset      # 忽略上次记住的窗口位置
```

## 交互

| 操作 | 行为 |
| --- | --- |
| 拖卡片头部 / 胶囊 | 挪整个浮窗（位置记在 UserDefaults，下次原地出现） |
| 点行 | action 经宿主排队 → 浏览器端 `openSession`，DSH 应用同时被带到前台 |
| 右键卡片 | 打开 DSH / 复位位置 / 退出浮窗 |
| 点卡片以外 | 穿透到桌面（只有卡片、胶囊、菜单矩形可点，其余是「空气」） |
| 点胶囊 | 收起 / 展开，浮窗高度跟着卡片内容变（顶边不动） |
| 点更新面板里的链接 | 交给系统默认浏览器打开 |

## 隐私与安全

- 渲染页是本地 `file://` 文件，**全程零网络**：所有数据由壳轮询宿主后注入，
  React 也是包内 `desktop/vendor/` 里的本地副本；
- 壳对宿主的每个请求都带握手 token；文件 0600 只有当前用户可读；DSH 重启 token 轮换，
  旧壳收到 401 会自动重读握手文件；
- 快照在宿主里只存**内存里的一份最新帧**，不落盘、不出本机；宿主进程退出即消失；
- 快照经过裁剪（`client.js` 的 `dockPayload`）：不带会话正文，`projectionValues` 只留
  模型选择 / 子代理计时 / 待办种类，浮窗上不出现任何对话内容。

## 边界与已知取舍

- **准实时**：发布器 1 秒一拍（空闲 8 秒），浮窗比页内卡片慢约 1 秒；
- **皮肤不同步**：WKWebView 用 nonPersistent data store，浮窗里的皮肤选择重启后回到默认；
  页内换肤不会同步过去，想要同款在浮窗里右键…不，换肤在浮窗里是同一套皮肤菜单，再选一次即可；
- **一个壳对一个实例**：壳按握手文件挑一个 origin 轮询；多实例可以多开几个壳
  （`--origin=` 各指一个）；
- 浏览器页面关掉后浮窗 30 秒内转入离线态（卡片变暗 + 提示），页面回来自动恢复。

## 排查

| 现象 | 先看 |
| --- | --- |
| 「等待 DSH 页面连接…」不消失 | ① dsh 是否在跑：`ls ~/.dsh/agent-tree-dock-*.json`；② 浏览器页面是否开着（地址栏要有这个 dsh 实例）；③ `--verbose` 看轮询日志是 200 还是 401/连接拒绝 |
| 401 | DSH 重启过、token 轮换了：正常情况下壳会自愈；一直 401 就重启壳（它会重读最新握手文件） |
| **在 DSH 里拖卡片，拖不出窗口** | 页内卡片永远出不了浏览器窗口（网页画不到视口外），这是物理边界。要「跑到窗口外」得启动桌面浮窗（见上）：`npx -p dsh-plugin-agent-tree dsh-agent-tree-dock` |
| 卡片点不动 / 拖不动 | `--verbose` 看 `pass rects` 数量；为 0 说明页面还没上报布局，等 1 秒，或 `--reset` 复位 |
| 窗口高度和卡片对不上 | 收起 / 展开一次让它重新量；仍异常带 `--verbose` 截 `layout` 日志反馈 |
| **浮窗内容和 DSH 里那个卡片对不上** | 浮窗镜像的是「某一个实例的页面」发布的快照（发现时优先挑活跃的那个，也可 `--origin=` 指定）。桌面 App 还没升到 0.1.6 时，App 自己的页面发不了快照，浮窗只能连别的实例——它的树看不到 App 里**正在跑**的会话（其它实例的运行事件流它收不到），这是数据边界不是 bug；App 升级重启后两者 1:1。 |
| 点了行没反应 | 会话是在「发布快照的那个页面」里打开的：页面是别的浏览器标签页时，跳转发生在那个标签页里；`--verbose` 看 `open → 200` 确认指令送达了 |
