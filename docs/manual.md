# 使用手册：这张卡怎么读

简体中文 · [English](manual.en.md)

```
┌──────────────────────────────────────────────────┐
│ ● 5 个 agent 在跑 · 2 个定时                  ▾  │ ← 头部：统计 + 折叠
├──────────────────────────────────────────────────┤
│ ▾ ● dsh                          2 个 workspace  │ ← 顶层 agent：这个 DSH 实例
│ ├─ ▾ proj-alpha                              2  │ ← workspace
│ │  ├─ ▾ ● ⏰ Refactor billing flow  8m  v4.1-pro  │ ← 对话（绿点，挂了定时）
│ │  │  ├─ ● Explore repo structure      1m5s     │ ← subagent（蓝点）
│ │  │  │  └─ ● Run unit tests              9s     │ ← 孙代理（紫点）
│ │  │  └─ ● Write migration plan          31s     │
│ │  └─   ⏰ Fix flaky login test      2h  v4.1-flash │ ← 有定时、当前空闲
│ ├─ ▾ my-repo                                 1  │
│ │  └─ ● Triage CI failures        v4.1-pro       │
│ ▾ ● claude  proj-alpha                 12m 3%    │ ← 顶层 agent：本机 claude（和 dsh 同级）
│ │  └─ computer use ×2                    41m     │ ← 它的子进程（按种类归组）
│ ▾ ● codex   ChatGPT                 69h35m 2%    │
│ ├─ MCP ×2                                2h50m   │
│ ├─ computer use ×2                        41m    │
│ └─ code mode                              41m    │
│ 会话 6 · 子代理 3 · 运行中 5（live）             │ ← 自检行
└──────────────────────────────────────────────────┘
```

## 1. 头部

| 文案 | 含义 |
|---|---|
| `● 5 个 agent 在跑 · 2 定时` | 5 个会话/子代理处于 running；另有 2 个会话有 active 定时任务 |
| `空闲 · 2 个定时待命` | 没有正在跑的，只有定时任务等着 |
| `🌳 Agent Tree Dock 1 待处理 🤖5 ⏰3 ⌃` | 收起状态：一颗圆头圆脑的胶囊（待处理 / 在跑的 agent / 定时任务三个计数，为 0 的不显示） |
| 窗口头「—」按钮 / 点胶囊 | 手动收起 / 展开；手动操作优先于自动折叠 |
| 窗口头小 T 恤按钮 | 展开皮肤列表、切换皮肤（见 1.6） |
| 窗口头转圈按钮 | 检查插件更新：点一下才联网查一次 npm，显示最新版本 / 升级命令（见 1.7） |

自动折叠规则：`running === 0 && scheduled === 0` 时收起；一旦有活儿自动展开（除非你手动收起了）。

## 1.4 需要你拍板的会话

agent 提问（`ask_user_question`）、等你批准一次操作、等你审阅计划时，会话会停在「等输入」状态，不算在跑。
卡片把这类会话**放在最上面**，并换成琥珀色 + 小徽标：

```
├─ ● 智力研发团队 1            待答   v4.1-pro
│  └─ ● 计划审阅               待审
```

- `待答`：agent 提了问题，等你选/答。
- `待批`：等你批准一次操作（命令、写文件、联网等）。
- `待审`：等你审阅计划（plan review）。

这类行排在「在跑」之前，所以永远不会因为「没在跑」被折叠掉；标题栏也会变成
「N 待处理 · M 在跑 · K 定时」。

## 1.5 层级

**顶层是「本机上的 agent」列表**：`dsh`（这个实例）和每个外部 `claude` / `codex` 是同级节点，
各自往下展开：

```
dsh（这个实例）                  claude / codex（本机其它 agent）
└─ workspace                     └─ 子进程（按种类归组）
   └─ 对话
      └─ subagent
         └─ 孙代理 …
```

所以从 `dsh` 往下是 4 层（workspace → 对话 → subagent → 孙代理），每个顶层 agent 都可以单独折叠。

## 1.6 皮肤（换皮肤 / 配色）

窗口头里、「—」左边有一个小 T 恤按钮，点开是六套内置皮肤：

| 皮肤 | 配色 | 细节 |
|---|---|---|
| 默认 | 跟随 DSH 主题 | 浅色白卡 / 深色深灰卡，不加装饰 |
| 樱花 | 粉白 + 樱色 | 头部粉色 banner、重画的樱花 icon、粉色边框 / 阴影，2/3 层圆点转粉 / 紫；一整枝樱花长在卡片外面（左上 / 左下） |
| 鲸鱼娘 | DeepSeek 蓝 + 海面渐变 | 蓝色 banner、重画的鲸鱼 icon、蓝色调文字与计数；浪花小鲸鱼从右上角探出来 |
| 鲸鱼娘·小姑娘 | 天蓝 + 淡粉 | 手绘 Q 版小姑娘（双马尾、鲸鱼尾巴发饰、水手领）从卡片右上角探头，胶囊上也有她 |
| 竹林 | 草绿 + 竹叶留白 | 水彩竹子从卡片左右两侧长出来，叶子伸到框外，草绿 banner |
| 兰花 | 淡紫 + 粉调 | 一丛兰花从右上角探出、一丛从左下角长出，暗紫色文字与边框 |

- 点一套立刻生效，选择存 `localStorage: dsh-agent-tree:skin`；
- 樱花 / 鲸鱼娘 / 小姑娘 / 竹林 / 兰花都带**外框装饰**：透明底素材渲在卡片外层、卡片后面，只露出框外那一部分，像从 dock 边缘长出来；
  收起成胶囊时第一张装饰会贴到胶囊右上角；
- 收起后的胶囊同样套用皮肤（胶囊里没有入口，展开就能换）；
- `Esc` 或再点一次小 T 恤关闭列表；
- 每套皮肤都有自己的深色变量，跟随 DSH 的 `body[data-ds-dark-theme]`。

想自己加一套（或只改几个颜色）不用改代码：往 `window.__DSH_AGENT_TREE_SKINS__` 注册一组 `--dat-*` CSS 变量
和可选的 `decor` 外框装饰图，完整的变量表 / icon / banner / 装饰写法和示例见 [皮肤指南](skins.md)。

## 1.7 检查更新

窗口头三个 ghost 按钮的中间那个是**转圈按钮**（`—` 左边第二个）：

| 状态 | 看到什么 |
|---|---|
| 空闲 | 只有一圈淡淡的箭头；有新版时按钮右上挂一个小圆点 |
| 点击后 | 图标开始转圈，标题层下面展开一条检查面板 |
| 已是最新 | `✓ 已是最新 · v0.1.5` + 「刚刚 / N 分钟前检查过 npm registry」 |
| 有新版 | `↑ 发现新版本 vX`（当前 v0.1.5）+ 一条可复制的升级命令 |
| 失败 | 红色提示 + 「浏览器拿不到 npm registry（离线或网络被拦）」，可再点重试 |

- **只在点击时联网**：向 `https://registry.npmjs.org/dsh-plugin-agent-tree/latest` 发一次只读 GET，
  不带 cookie、不带 token、不自动轮询、不上报任何本机信息；
- 上次检查结果（最新版本 + 时间）存 `localStorage: dsh-agent-tree:update`，所以刷新后小圆点还在；30 分钟后视为过期；
- 面板里的升级命令是 `dsh plugin --profile web add dsh-plugin-agent-tree@latest`，点「复制命令」即可；
- `client.js` 里的 `PLUGIN_VERSION` 必须和 `package.json` 的 `version` 一致（`npm run verify` 会检查），发版时两个一起改。

## 2. 树行元素

从左到右：

| 元素 | 含义 |
|---|---|
| `├─ └─ │` | git log 风格连接线，表示层级；每深一层多三格缩进 |
| `▾ / ▸` | 这一行有子代理，可展开 / 已收起 |
| `●` | 状态点：颜色见下表 |
| 标题 | 会话标题（`displayTitle`），过长省略；运行的会话字更粗更深 |
| `⏰` + `8m` | 标题前的小闹钟表示这行挂了定时 / 循环任务；右侧是倒计时：`now` / `<1m` / `8m` / `2h` / `3d`（到期显示 `now`，闹钟不消失） |
| `v4.1-flash` | 模型标签（右侧对齐）：来自 `modelSelection`，`deepseek-` / `anthropic-` 前缀会去掉 |
| `1m5s` | 运行或已运行时长（subagent 行才有）：`45s` / `12m` / `1h5m` |

## 3. 颜色

| 颜色 | 含义 |
|---|---|
| 绿点 | 顶层对话在自己的会话里跑 |
| 蓝点 | 第 2 层 subagent |
| 紫点 | 第 3 层及更深（孙代理……） |
| 灰点 / 浅字 | 已结束，但为了让层级完整仍保留的行 |
| 橙点 / 绿点（底部段） | claude 进程 / codex 进程 |

## 4. 模型标签的继承

subagent 的 `modelSelection` 常常为空，这时用最近一个祖先会话的模型，悬停会显示「继承自上级」。
所以「这一行用的是哪个模型」永远有答案，不会留白。

## 5. 定时任务行

DSH 的 Automation tasks（`schedule.catalog()`）驱动的是「间歇式工作」的会话：它们大部分时间空闲，
到点自己跑一次。卡片会把这些会话**即使不在跑也列出来**：

- 标题前固定一个 `⏰`（小闹钟），一眼认出「这行是循环任务」；
- 右侧是距下次触发的倒计时；
- 刚跑完、倒计时到期时显示 `now`，但 `⏰` 保持——正在跑的循环任务不会看起来像普通会话。

点它同样能跳过去看上一次跑出来的东西。

## 6. 本机其它 dsh 实例

同一个 `~/.dsh` 下可以同时开好几个 `dsh web --port 30xx`。浏览器这一侧只看得到自己连着的那个实例，
但进程表和会话目录是共享的，所以宿主半部可以只读地把别的实例"接"进来：

- `ps` 找 `dsh ... web` 进程（排除自己）；
- `lsof -a -p <pid> -iTCP -sTCP:LISTEN` 拿它监听的端口（`3080` 那个通常还会多一个 `3081`）；
- `lsof -p <pid> -Fn` 里 `~/.dsh/sessions/<项目>/session-<id>/` 就是它当前打开着的会话。

卡片上每个实例是一个顶层节点：

```
▾ ● dsh :3083                2 个会话 · 2 子代理
├─ ● 推进 backlog 任务并设循环     1m
└─ ▾ ● PMO                 2子   6m
   ├─ ● 巡检流水线               4m
   └─ ● 汇总日报                 7m
```

- **只列还在干活的会话**：有本地实时状态就听状态（在跑 / 等你拍板），没有就按「最近 5 分钟内有活动」判断；
  几小时前停着的会话不显示，整个实例都没有活儿时连实例节点一起收掉。
- 会话标题来自共用的会话目录，所以和那个实例里看到的一致；右侧是"多久没动"。
- `N子` 是这个会话挂了多少个 subagent（按会话表里的 `parentId` 数），点 `▸` 展开成缩进的子会话行（最多 6 个）。
- 点实例行 / 会话行 → 新标签打开那个端口的页面（做不到直接深链到具体会话）。
- 会话 id 不在本实例会话表里（比如另一个 `DSH_HOME`）时不显示行，只在 tooltip 里提示有几个。
- 最多 4 个实例、每实例 6 行，避免卡片变长。

## 7. 本机外部 agent（和 dsh 同级）

宿主半部的只读探测，列出本机正在跑的 `claude` / `codex` CLI。它们**和 `dsh` 一样是顶层节点**
（同一套行规格：同样字号、同样圆点、同样折叠），区别只有圆点颜色（claude 橙 / codex 绿）：

```
▾ ● claude  proj-alpha        12m 3%
▾ ● codex   ChatGPT        69h35m 2%
```

- 行名（`label`）的取值顺序：该 codex 会话的第一条真实用户消息（跳过 `environment_context` / `AGENTS.md` 注入）
  → 进程真实 cwd 的目录名 → 命令行里的 `--cwd/--cd/-C` → `ChatGPT`（桌面端 backend）→ 空。
- 只显示前 8 条；结果缓存 3 秒；接口需要登录态（未登录 401）。
- 目的是「我在 DSH 里干活时，本机还有没有别的 agent 在偷偷跑」；点这一行可折叠子树。

### 6.1 外部 agent 的子进程

`claude` / `codex` 的子进程按 `ppid` 挂成子树；同一种子进程会归组成一行：

```
├─ ▾ ● codex  ChatGPT        69h35m 2%
│  ├─ MCP ×2                    2h50m
│  ├─ computer use ×2             41m
│  └─ code mode                   41m
```

- `×N` 表示有几个同类子进程，右侧显示其中跑得最久的时长；
- 点进程根行可以折叠它的子树；
- 子孙里如果又是一个真正的 agent CLI，会单独作为根出现，不重复挂。

### 6.2 codex 的子对话（subagent threads）

codex（CLI 和 ChatGPT 桌面端）每开一个会话都会写一条 rollout：`~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`。
第一行是 `session_meta`，里面就有 `thread_source: subagent`、`parent_thread_id`、`agent_nickname`、`agent_path`。
插件只读这些头部、按 `parent_thread_id` 串成树，挂在 codex 那一行下面：

```
▾ ● codex ChatGPT              69h35m 2%
   ├─ ● Hubble   advance_review_logic       running
   ├─ ● Carson   review_nextarchive_code    16m前
   ├─ ● Wegener  review_nextarchive_triage  1h42m前
   ├─ MCP ×2                                2h50m
   └─ computer use ×2                        41m
```

- 2 分钟内活动过标 `running`（绿点加粗），否则显示「最后活动多久前」。
- 找的是哪条主会话：先按进程 cwd 匹配，worktree 里跑的就取 cwd 互为前缀的那条；
  ChatGPT 桌面端进程 cwd 常常是 `/`，这时优先挑 `originator` 带 `Desktop` 的会话。
- 最多 8 个子对话、最深 3 层。只读本机、不联网、不外发。

### 6.3 codex 那行的名字

行名不是目录名，而是**这条 codex 会话的第一句真实需求**（跳过 codex 自己塞的 `environment_context`、
`AGENTS.md instructions` 这类上下文），后面跟一个灰色的目录小标签：

```
▾ ● codex 推进一下能推进的任务，看看流水线…   devline   69h35m 2%
```

- 取不到（rollout 刚建、还没写用户消息）才回落到目录名 / `ChatGPT`。
- 同一 cwd 下有多个 codex 进程时，按时间各认领一条会话，所以不会出现两行同名。

## 8. 交互

| 操作 | 效果 |
|---|---|
| 点一行 | 跳到该会话（subagent 会落到它自己的对话） |
| 点 `▾/▸` | 折叠 / 展开该节点的子代理 |
| 拖窗口头 | 移动卡片，位置存 `localStorage: dsh-agent-tree:pos` |
| 点窗口头右上角「—」/ 点胶囊 | 收起成胶囊 / 展开整张卡 |
| 点窗口头小 T 恤按钮 | 打开皮肤列表，点一套即换皮肤 |

## 9. 刷新节奏

| 数据 | 频率 |
|---|---|
| running 状态 | 官方实时事件 `api-session/status`（`live`）；拿不到时 1s 轮询快照（`poll`） |
| 定时任务 | 事件 `schedule/changed` + 15s 轮询兜底 |
| 外部进程 | 5s 一次（宿主侧再缓存 3s） |
| 倒计时 / 时长 | 每秒重算显示 |

## 10. 自检行

`会话 N · 子代理 M · 运行中 K（live|poll）`

- `N` 是快照里能看到的会话数，`M` 是其中 `origin: subagent` 的数量；
- `K` 是判定为 running 的数量；
- `live` 表示用的是官方实时事件，`poll` 表示回落到了轮询 —— 如果长期是 `poll`，说明这个 DSH 版本的全局
  props 里没有状态 store，可以据此提 issue。

## 11. 已知限制

- 只显示**当前 Web 实例**的会话（别的 profile / 别的机器看不到）。
- 运行状态以 DSH 的状态事件为准；如果某个子代理在 DSH 里已经结束、但事件还没到，可能短暂多显示一两秒。
- 卡宽固定 288px，超长标题会省略；想加宽改 `client.js` 顶部的 `WIDTH`。
- UI 文案暂时是中文。
